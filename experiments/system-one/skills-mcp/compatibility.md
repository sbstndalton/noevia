# Compatibility and adoption evidence

Scope: the offline skills/MCP experiment for [issue #19](https://github.com/sbstndalton/noevia/issues/19). Runtime claims below describe the audited application contracts at `fd5f0e0689ada46ad9a8c7ee518a11e5128abba3`, checked against this branch on 2026-09-23. They do not describe deployment or a provider certification. No live model or MCP candidate was contacted for this slice.

## Runtime/provider matrix

| Surface | Present contract | Compatibility limit | Selection/adherence/completion evidence in this experiment |
| --- | --- | --- | --- |
| Project Markdown skills | `instruction-skills.cjs`: project-owned `.md`, scalar frontmatter, 32 KiB total, reviewed content hash and explicit enablement; exchange snapshot | Not a full YAML/package loader. `license`, `compatibility`, `allowed-tools` are informational. `requires` names existing selected boxes; it cannot enable them. | Synthetic loader checks only; model quality unmeasured |
| Generic answering providers | `providers.cjs` uses one OpenAI-compatible chat-completions shape and per-provider headers; reviewed instructions enter the model-facing context | Endpoint/API compatibility does not establish tool-call support, instruction adherence or equal behavior. Native Anthropic/other vendor APIs are not implied by this adapter. | No cross-provider run; all model/provider quality cells pending |
| Existing skill embedding router | `chat-skill-routing.cjs`: caller-supplied embeddings, threshold and near-tie abstention, at most one body; prompt body bounded to 12,000 characters | Requires working embeddings. Off/error/no clear match loads no body and retains the metadata index. Embeddings rank relevance, not authority. | Scripted embedding vectors test routing behavior only |
| Existing toolbox routing | `chat-tool-routing.cjs`, `tool-router.cjs`, `toolboxes.cjs`: narrow selected boxes, dependency closure, deployment offers, count/token budgets and execution allowlist | Fallback retains the permitted selected set; `more_tools` can widen only within that ceiling. Account blocks/readiness still bind. | Synthetic contract checks; no new latency or task-quality claim |
| System-One configured service | `decision-settings.cjs` / `decision-endpoint.cjs`: private operator/admin service; `choice` adapter and step supervision; bounded deadline | Already used for model-role routing and supervision. No production skills/MCP selector is introduced here. | Skills/MCP quality pending |
| llama.cpp decision readout | `decision/backends.cjs`: `llamaLogitBackend` supports `choice`; uses `/props`, `/tokenize`, `/apply-template`, `/completion` | These are runtime-specific APIs, not generic chat-completions compatibility. Token/answer-position checks can reject a readout; relative label scores are not calibrated correctness probabilities. | Not invoked; quality pending |
| Rank backends | Same module: `embedBackend` ranks supplied scores; `llamaRerankBackend` uses `/v1/rerank` and requires complete results | A backend supporting `rank` need not support `choice`. A remote endpoint must also pass decision locality policy; a backend label is not authorization. | Synthetic supplied scores only; live reranker pending |
| MCP client | `mcp.cjs`: Streamable HTTP `initialize`, `tools/list`, `tools/call`, JSON or SSE response body, session/version handling | SSE response parsing is **not** legacy SSE transport support. No stdio/process launcher, prompts/resources/sampling/elicitation or server-initiated requests. Function-schema conversion may reject schemas; `outputSchema` is not retained. | Existing client fixtures are protocol evidence, not candidate interoperability |
| Executable skills | No execution capability granted by instruction-skill loading | Unsupported; no install, server startup or host-shell fallback. See [separate design](script-execution-design.md). | No execution performed |

The experiment compares deterministic contracts on frozen synthetic snapshots. A loaded body is not proof that a model followed it; a permitted schema is not proof of a successful call. Scripted expected IDs, approval fakes and estimated schema tokens must not be presented as measured model accuracy, real write safety, end-to-end latency or token consumption.

Future authorized measurements must identify model/version, provider/runtime build, execution host, embedding model, dependencies, permissions and context budget; freeze fixture/config/catalogue hashes and a held-out set; repeat stochastic cases at least three times. Report selection accuracy, actual body/schema exposure, instruction adherence, task completion, fallback rate, unauthorized actions, wall time and actual input/output tokens separately. Zero unauthorized actions and no held-out completion regression are adoption gates. Until that evidence exists, production adoption is **deferred**; rollback is to keep the experiment unwired and retain current loaders.

## MCP candidate dispositions

These are the existing 2026-09-23 source-review decisions, not a fresh audit or pinned code qualification. None was installed or executed. README transport claims are only screening evidence.

| Candidate | Observed source evidence | Decision and remaining gate |
| --- | --- | --- |
| [getfounded/mcp-tool-kit](https://github.com/getfounded/mcp-tool-kit) | GitHub archive status independently confirmed; README describes stdio/SSE and broad dynamic registration | **Reject adoption in this slice.** Documented transports and broad registration do not fit the current client/curated manifest. Historical catalogue ideas only. |
| [ezyang/codemcp](https://github.com/ezyang/codemcp) | Maintainer describes it as obsolete; README describes predeclared commands, Git edits and auto-accept | **Historical reference only.** Do not replace Code harnesses or inherit auto-accept. Predeclared capabilities/recoverable edits are design references. |
| [modelcontextprotocol/servers](https://github.com/modelcontextprotocol/servers) | Repository describes educational reference implementations rather than a production bundle | **Qualify individually.** Useful protocol/schema references; no blanket approval of servers or transitive dependencies. |
| [nickclyde/duckduckgo-mcp-server](https://github.com/nickclyde/duckduckgo-mcp-server) | README describes search/fetch, caching/rate limits, stdio plus SSE/Streamable HTTP and host/origin controls | **Defer.** Streamable HTTP is plausible transport fit only. Compare synthetic retrieval/citation quality, latency, rate limits, fetch SSRF/redirect controls, output size and total tokens against configured web search before proposing adoption. |

For any future integration, pin source revision/artifact and license; inspect maintenance and dependency provenance, startup cost, transport handshake, schema conversion, credential handling, network/egress, output bounds, disconnect/cancellation and uncertain-call behavior. Map each tool to an existing reviewed manifest/read-write classification and account policy. Require explicit operator configuration and an integration rollback that removes the offered box without widening permissions. Source discovery, schema loading, server startup and package installation remain separate actions.
